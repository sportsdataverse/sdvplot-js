[Recharts](https://recharts.github.io) draws a chart from React components, and lets a series or an axis hand each
point or tick to a function of your own. `@sportsdataverse/sdvplot/recharts` gives you those functions: team logos and
player headshots as a series' `dot` or `shape`, team logos as an axis' `tick`, and team colours for each series. It
never imports recharts (install `recharts` 3.2 or later beside it, an optional peer), and it is synchronous, so load the
league first (`loadLeague`). The court, field or rink backdrop is a component, `<SurfaceBackdrop>`, in
`@sportsdataverse/sdvplot/react`. Each chart below is drawn by Recharts in your browser.

## Logos on a category axis, and dark mode

`logoTick({ league, size })` is an axis' `tick`: each category that names a team draws the team's logo, `size` px
tall, where its label would be (under a bottom axis, left of a left one). A category that resolves to no logo keeps its
text label, as the ECharts adapter does. `teamColorPalette(league, teams, { background })` gives one colour per team;
with `background`, a colour under 3:1 contrast against it gives way to the team's other colour, or is lightened (on a
dark background) or darkened until it reads.

## A logo at the end of each line

`logoDot({ team, league, size })` is a series' `dot`: each point draws the logo of the team in its data row's `team`
column, centred on the point. `last: true` draws only the series' final point, which turns a trend line's last value
into an end-dot. It needs the series' points, which Recharts hands a `<Line>` or `<Area>` `dot` but not a `<Scatter>`
`shape`: there every point is drawn, with one warning. A team with no logo draws nothing and warns once. `size` is a
height in px (1 or more), not a fraction of the plot as the spec adapters' `height` is: a fraction throws.

<Live id="sdvplot/recharts/afc-west-win-trend" />

## Headshots as points

`headshotDot({ player, league, size })` draws each row's ESPN headshot (600:436) instead; give it to a `<Scatter>` as
its `shape`. `logoDot` works there too. An id with no headshot draws nothing and warns once.

<Live id="sdvplot/recharts/afc-qb-headshots" />

## A court under the shots

`<SurfaceBackdrop league team displayRange />` is a child of the chart, placed before the series so it is drawn under
them (Recharts 3 renders any element there; `<Customized>` is deprecated). It draws the surface in the axes' units, so
both axes must be `type="number"` with a numeric `domain` in the surface's units: the surface's bbox (sporty's
`surface(...).bbox`) fills the plot area, any other range in those units shows part of it. Reversed and log axes are not
supported: on them, and on a category axis, it draws nothing and warns once (recharts 3.8 or later is needed to tell a
reversed or log axis apart; on 3.2 to 3.7 it would draw the surface mirrored or stretched). recharts and `@sportsdataverse/sporty` load when it first renders,
never with `sdvplot/react`, and a missing one throws `OptionalDependencyError` then. On the server it draws nothing; it
appears once the page's scripts run.

## Images that travel with the file

`embedSources(urls)` fetches each logo once and maps it to a data URI; pass the map as `embed` and every `<image>`
carries its bytes instead of a link, so a copy of the chart's SVG shows the logos offline.

<Live id="sdvplot/recharts/embed-sources" />

## Reading back what was drawn

Every image carries the `data-sdv-*` attributes that `drawnMarks` from `@sportsdataverse/sdvplot/testing` reads, so a
test can render the chart (jsdom, or a browser) and check which teams were drawn where. Recharts hands a render prop
pixels and no plot height, so a mark's `x`, `y` and `height` there read in px, not in data units and as a fraction of
the plot as the spec adapters' do.
