Plot-native marks and interactivity (J39-J42).

- **Open image marks.** `logos`, `wordmarks` and `headshots` compute only the image URL, its size and skip-and-warn; every other Observable Plot image option passes through (`tip`, `href`/`target`, `title`, `fx`/`fy`, `sort`/`filter`/`reverse`, `dx`/`dy`, `className`, `clip`, `opacity`, `channels`). Plot's row-preserving transforms wrap them (`dodgeY`/`dodgeX` beeswarms, `stackY`, `windowY`, `selectLast`, `pointer`); a transform or initializer that makes new rows (`bin`, `group`, `hexbin`, which keeps the data but bins the channels) throws `InputError`, here and on the shot marks. A caller's `render`, `transform` and `initializer` are composed with sdvplot's, never replaced (`Plot.pointer` stays outermost). New option types `ImageMarkOptions` and `ImagePassThrough`.
- **Tips, opt-in.** `tip: true` adds Plot's own tip, and the pointed row is the figure's `value` (with an `input` event). Defaults: the team on the image marks, named as its image is ("KC" for rows keyed by `team_id` too), or the player id on headshots; attempts, FG%, league FG% and the shrunk difference on `shotCells`; the zone, plus makes/attempts and FG% given the new `stats` option, on `shotZones`; distance, FG%, league FG% and share on `shootingSignature` (new `tip` option). A tip object's `format` merges over sdvplot's key by key. `shotZones` and `shootingSignature` return their tip as the last mark, so nothing they draw paints over it. Server rendering adds only an empty tip group.
- **Accessible names everywhere.** Every image is named by its subject ("KC logo", "KC wordmark", "3139477 headshot"), by the resolved team whatever id system the rows use (`team_id` included): the Plot image marks and `axisLogos`, the Vega image layers and `withAxisLogos`, and d3's `appendLogos`/`appendWordmarks`/`appendHeadshots` (new `ariaLabel` accessor option). `shotZones` names each path by its zone and `shotCells` each cell by its makes, attempts and FG% ("147 of 181 made, 81.2%"); the shooting signature's ribbon is named in Plot and d3, and `appendLegend` names its colour bar. A titled `teamTiers` figure is labelled by its title. sporty describes every surface it draws, with an `ariaDescription` option and the default "nba basketball surface" and so on: `surfaceMark`, `toSVG` and d3's `appendSurface` (a new optional fifth argument), and so sdvplot's `surface` and d3 `appendSurface` (new `ariaDescription` option). With default options these attributes are the only change to the SVG the shot marks, `toSVG` and `appendSurface` write. The README says where Plotly, ECharts and Chart.js charts get their accessible name.
- **Shot marks.** `shotCells` and `shotZones` draw the caller's `cells` and `areas` as the mark's data and take Plot's geo options (`GeoPassThrough`: `fx`/`fy`, `channels`, `title`, `href`, `clip`, ...). `shotCells` passes them all to its cells; `shotZones` passes them to its zone paths except `channels`, which go to the zone tip. A zone's tip anchors on points inside the zone, so the C-shaped mid-range is reachable.
- **Pass-through on `axisLogos`, `meanLines`/`medianLines` and `teamTiers`.** `axisLogos` takes Plot's axis options (`AxisPassThrough`; a caller's margin on the anchored side wins, and a caller's `render` wraps sdvplot's tick swap), the reference lines take Plot's rule options (`RuleLinePassThrough`, so `fx`/`fy` give a mean per facet), and `teamTiers` takes `tip`.
- `drawnMarks` (`sdvplot/testing`) reports a Plot image's x and y as the data value behind the channel: `null` where a transform such as `dodgeY` computed the position, and a Date as its time in ms.

Breaking, before the first publish (so declared here, not as a major bump):

- `shotCells`' `clip` is renamed `dropOutside`, so Plot's own `clip` passes through.
- Image marks: `x` and `y` are Plot channel specs and optional (a transform such as `dodgeY` may supply `y`); `title` is Plot's channel; `ariaLabel` is Plot's per-image channel, so a string is a column name (the old string option named nothing); `alpha` is the Python sdvplot name for a constant `opacity`, kept for parity, and passing both throws `InputError`; `r` is the dodge collision radius and never clips or sizes an image (Plot's own image mark uses `r` to clip the image to a circle).
- `ShotCellsOptions.stroke` and `strokeWidth`, and `ShotZonesOptions.fillOpacity`, widen to Plot channel specs.
- A `shotCells` or `shotZones` path's datum is now its index in the caller's input, not a built feature (draw order is unchanged).
- Image marks given column-name `x`/`y` now label the axes from those names, as any Plot mark does (`logos(rows, { x: "wins", y: "pf" })` gains `wins →` and `↑ pf`); before, sdvplot handed Plot pre-placed arrays, so there were none. Pass `x: { label: null }` / `y: { label: null }` to the plot to hide them. Apart from the accessible names, this is the only change in the default output of the earlier logo marks.
