reactablefmtr cell formatters. Five new column kinds with reactablefmtr 2.1.0's defaults: `dataBar` (`data_bars`: fill, ramp, gradient, per-row `colorRef` or team colours via `team` + `league`, seven text positions, left or right bars, diverging bars for negatives, round edges, and a logo, wordmark or headshot mark), `iconSet` (`icon_sets`), `iconAssign` (`icon_assign`), `mergeStack` (`merge_column`, with an optional mark; `mergeStackTeamColor` stays) and `bubble` (`bubble_grid`). Existing kinds gain reactablefmtr options: `colorRanks` takes `colorRef` / `team`, `bias`, `span`, `showText` and `evenBreaks` (`color_tiles`, `color_scales`), `colorPills` takes `colorRef` / `team` (`pill_buttons`), and `highlight` takes `"min"`, `"max"` or `"both"` in place of a predicate (`highlight_min`, `highlight_max`, `highlight_min_max`). Every column takes `tooltip: true`, the cell's value as its `title` attribute. Icons are an inline-SVG set (`ICON_NAMES` from `./html`), not an icon font. `GT_ALIASES` maps the reactablefmtr names. `highlight`'s `when` and `fill` are now optional in the spec type: code that reads a built `highlight` column's `when` (for example to pass it to `matches()`) needs an `undefined` guard; `build()` throws when a highlight has neither `when` nor `extreme`. `colorRef` / `iconColorRef` values must be hex colours; any other value (blank, named, `url(...)`) is treated as blank, and a blank or unknown `iconRef` falls back to the bucket icon. CSS values now also reject `url(`.
