Linked interactivity (J31): `createSelection` selection store in the core; `sdvplot/interact` with `brushFilter`, `highlight` and `linkSelection` (optional peer `d3`); `linkIds` and an `id` option on `logos`/`wordmarks`/`headshots` in `sdvplot/plot`; `useSelection` in `sdvplot/react`; `linkCursor` (a shared hover value followed through each figure's own scale: rule, band or ring), `nearestHover`, `tooltip`; `brushFilter` 1-D, `empty`, `scales`; `linkSelection` `hover` and `select: "toggle"`.

- **Core.** The store holds `hover`, `selected`, `predicate` (a brush region as a row test) and `cursor` (one shared hover value, `{ field, value }`), with one notification per change and none for a change that changes nothing. Helpers `focusIds`, `toId`, `sameIds` and `sameCursor`; types `Cursor`, `RowFilter`, `SelectionState`, `SelectionPatch` and `SelectionStore`. `sdvplot/interact` also exports `hasDom`. Every interact call is a no-op without a DOM, so server-rendered markup is unchanged; a bad option still throws `InputError` in Node.
- **`id` on `logos`, `wordmarks` and `headshots`.** The new option sets the link id stamped as each image's `data-sdv-id` (`id: "team"` for a table keyed by abbreviation). Without it the stamp is the resolved ESPN team id ("12" for KC), or the player id on headshots. The ids follow their rows through `sort`, `filter`, facets and `Plot.dodgeY`.
- **`sizeRender(height, placed, kind, ids?)`.** The adapter-author helper takes an optional 4th positional parameter: the link ids by data row, stamped in place of each placement's resolved id.
- **`linkIds` on an image mark with `href`** stamps the `<image>` inside the `<a>`, so each row keeps one stamp. On any other mark with `href`, the stamp sits on the `<a>`. With `href`, `linkSelection`'s `select: "toggle"` throws `InputError`, because a checkbox cannot sit inside a link.
- **Teardowns clear only what they wrote.** `linkSelection`'s teardown clears the hover its own link wrote, as `nearestHover`'s `destroy` does. `linkCursor`'s teardown clears the cursor its own figure wrote. Each clears only while the store still holds exactly that value: another writer's hover or cursor survives, and a second teardown writes nothing. Then `linkSelection`'s teardown restores the view it changed, so a figure or table unlinked and kept on the page shows no store state, even mid-brush or mid-selection: the figure un-dims once the last link on it goes, its toggled marks get their own `role`, `tabindex` and `aria-checked` back, and the table drops the brush filter and the hover it showed. The store itself keeps a brush's region and a selection for the views still linked. To replace a linked figure, tear its link down before linking the new one. Otherwise the new figure's first sync reads the old figure's hover and warns that none of the linked ids is drawn.
- **Leaving clears only what the figure wrote.** `linkCursor` clears the store's cursor on `pointerleave`, `pointercancel` or a move off its axis only while the store still holds the value that figure wrote, in one update: a cursor an app `store.set` or another figure wrote since survives. Clearing or destroying a `brushFilter` clears its region, and `selected` only while it is still the set the brush wrote: a brush over exactly the ids another control selected first wrote no set of its own, so that selection survives. `nearestHover`'s `destroy` clears the hover it wrote even right after `update(points)`.
- **d3 scales as they are.** `brushFilter`'s `scales` and every `linkCursor` shape scale take a d3 scale itself (`D3ScaleLike`: `range()`, and on a band scale `bandwidth()` and `domain()`, are methods), so a d3-drawn chart needs no wrapper.
- **Edge inputs.** `brushFilter` given a scale with no finite pixel `range` spans the svg's box on that axis. Its `move(region)` tests rows against the region's own data bounds, never their pixel round trip, so a row on a bound is inside ("10+ wins" keeps a 10-win team). A mark stamped with an empty id (`toId`'s missing id) is no hover target and, under `select: "toggle"`, no checkbox. Every toggle checkbox has an accessible name: the mark's own (Plot's `ariaLabel` or `title` channel), else its link id. A `linkSelection` `hover` other than `true`, `false` or `{ id }` with a function `id` throws `InputError`, in Node too.
- **Styling** is a class toggle (`.sdv-focus` on the figure, `.sdv-hl` on the emphasised marks), never a redraw, through CSS custom properties with fallbacks: `--sdv-dim-opacity` (0.2), `--sdv-cursor-color` (`rgba(0,0,0,.2)`), `--sdv-cursor-width` (`10px`), `--sdv-tip-bg` (`rgba(34,34,34,.85)`) and `--sdv-tip-fg` (`#ddd`).
