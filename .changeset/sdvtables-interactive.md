Interactive tables and PNG export:

- `createTable(spec, rows, { pageSize, sort })`, a headless engine with no table-library dependency: sort (typed comparators, a column's own `compare`, missing values last both ways), per-column and global text filters, paging, `toggleColumn`, `setRows`, immutable snapshots and `subscribe`. Pure helpers `applyFilters`, `applySort`, `paginate`, `comparatorFor`, `withMissingLast`, `nextSortDir`, `findColumn`, `isMissing`, `NUMERIC_KINDS`. The link seam for linked figures: `rowKey` (spec and builder), `rowId`, `setExternalFilter`, `setSelection`/`getSelection`, `setHover`/`getHover` (a view attached after a hover reads it), and `select`/`hover` events.
- `renderHTML(table)` in `@sportsdataverse/sdvtables/html`: sort buttons with `aria-sort`, a search box, per-column filter boxes and a pager. `hydrate(el, table)` progressive enhancement re-renders only the table block. A keyboard grid (`j`/`k`/`h`/`l`/`s` and `/` hotkeys, arrows, Enter/Space row selection; `role="grid"` with one roving tab stop; `interactive: { hotkeys: false }` keeps only the arrows, Enter and Space), through `handleKeydown`/`keyAction` and the engine's `TableCursor` (`state.cursor`, `setCursor`). The handlers `handleClick`, `handleInput`, `handleHover` and `rowIdAt` are shared by `hydrate` and React; `renderInteractive`, `renderParts`, `assemble`, `tableHTML`, `attrsText`, `sortAria`, `tableRenderOptions`, `renderToolbar`, `renderPager` and `pagerLabel` serve custom renderers. In an interactive table colour scales and legends span all rows, so a value keeps its colour while the user pages, filters or sorts, and index row selectors count in the source rows (`selectRows` gains a `source` argument).
- `hydrate` timing: changes re-render once, on the next animation frame, however many land in it. One exception: a click, pointer move or key on the table while a change to its rows (a sort, filter, page turn or `setRows`) waits for its frame draws that change at once, so the event never reads an old row as the one now at its index. A click or key on a row this replaced acts on nothing, and Enter or Space on it is consumed, so the page does not scroll. A change that keeps the rows (a selection, the cursor, or a live feed re-sending a keyed row as a new object) waits for its frame. Hydrating an element again draws any change its previous binding still owed. A teardown drops a render still owed, and the next hydrate of that element redraws it first (even a change that left no row), so React StrictMode's mount, cleanup, mount leaves no stale rows. A hover the engine already holds (`getHover`) shows on attach.
- Row hover: every interactive table, linked or not, underlines the row under the pointer, or the row a linked figure hovers through `setHover` (the `sdvt-hover` class, a text-coloured underline at 3:1 or better in every theme). The hover re-renders nothing and survives the next re-render. A table holds one hover id. This differs on purpose from reactable, whose `highlight` defaults to `FALSE`; opt out with `tr.sdvt-hover>td.sdvt-cell{background-image:none}`, which wins wherever a page puts it: the built-in rule sits in `:where()`, so it weighs no more than `td.sdvt-cell`. The striped-row rule sets `background-color`, so a striped row keeps the underline too. `RowFilter`, the row test `setExternalFilter` takes, is sdvplot's own type, so a linked table applies a selection store's brush predicate as it is.
- `@sportsdataverse/sdvtables/react`: `useTable` and `<SdvTable/>`, whose server-rendered markup equals `renderHTML(table, { fonts: false })`; `fontsLinkFor(spec)` is the fonts `<link>` for the page head (`react` >= 18, an optional peer).
- `@sportsdataverse/sdvtables/export` (Node): `tableToPNG`, `htmlToPNG`, `socialCrop`, `batchToPNG`, `gridTables`, `stackTables`, `composePage` and `slug` (options `PNGOptions`, `SocialCropOptions`, `BatchOptions`), ports of sdvplotR's `gt_save_crop`, `gt_social_crop`, `gt_save_batch`, `gt_grid` and `gt_stack_tables` with the Python defaults (`playwright`, an optional peer).
- Static markup: an apostrophe is escaped as `&#x27;` (React's form), and every theme draws the subtitle on its own line (tufte and booktabs ran it into the title).
