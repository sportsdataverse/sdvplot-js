# @sportsdataverse/sdvtables

## 0.2.0

### Minor Changes

- edc5208: reactablefmtr in-cell charts. Three new column kinds draw each cell as an inline `<svg role="img">` with no script: `sparkline` (`react_sparkline`) and `sparkbar` (`react_sparkbar`) read an array column (the new `SeriesKey<Row>`: one array of numbers per row, `null` or any non-finite entry a gap), and `gauge` (`gauge_chart`) reads a number. They take reactablefmtr 2.1.0's defaults and options (highlighted points or bars, `statline`, `bandline`, value labels, an area, `minValue`/`maxValue`, a gauge's colour ramp, ends and `numberFormat`), with sdvplot's sparkline line width and point size of 1.5. Each chart's `aria-label` and `<title>` summarise its values (min, max, last, and the statline and band when drawn); a gauge fills by the absolute value, as reactablefmtr, and says so for a negative. `team` + `league` (or `colorRef`) colour each row, a team colour checked for 3:1 contrast on the table background. The chart size options are `chartWidth` / `chartHeight`, since `width` is the column's CSS width. `build()` rejects a `minValue` not below `maxValue` (and a negative gauge `minValue`), non-positive or non-finite sizes, `decimals` outside 0 to 20, opacities outside 0 to 1 and unknown point, statline or bandline names, each error naming the option. Sparkline and sparkbar columns are not sortable by default. `GT_ALIASES` maps `react_sparkline`, `react_sparkbar` and `gauge_chart`.
- 2c65767: reactablefmtr cell formatters. Five new column kinds with reactablefmtr 2.1.0's defaults: `dataBar` (`data_bars`: fill, ramp, gradient, per-row `colorRef` or team colours via `team` + `league`, seven text positions, left or right bars, diverging bars for negatives, round edges, and a logo, wordmark or headshot mark), `iconSet` (`icon_sets`), `iconAssign` (`icon_assign`), `mergeStack` (`merge_column`, with an optional mark; `mergeStackTeamColor` stays) and `bubble` (`bubble_grid`). Existing kinds gain reactablefmtr options: `colorRanks` takes `colorRef` / `team`, `bias`, `span`, `showText` and `evenBreaks` (`color_tiles`, `color_scales`), `colorPills` takes `colorRef` / `team` (`pill_buttons`), and `highlight` takes `"min"`, `"max"` or `"both"` in place of a predicate (`highlight_min`, `highlight_max`, `highlight_min_max`). Every column takes `tooltip: true`, the cell's value as its `title` attribute. Icons are an inline-SVG set (`ICON_NAMES` from `./html`), not an icon font. `GT_ALIASES` maps the reactablefmtr names. `highlight`'s `when` and `fill` are now optional in the spec type: code that reads a built `highlight` column's `when` (for example to pass it to `matches()`) needs an `undefined` guard; `build()` throws when a highlight has neither `when` nor `extreme`. `colorRef` / `iconColorRef` values must be hex colours; any other value (blank, named, `url(...)`) is treated as blank, and a blank or unknown `iconRef` falls back to the bucket icon. CSS values now also reject `url(`.
- 5946673: The 27 reactablefmtr themes, registered as `fmtr-<name>` (`fmtr-espn`, `fmtr-nytimes`, `fmtr-no-lines`, ...) with reactablefmtr's own colours, sizes, rules and padding, plus `fmtr-team`, reactablefmtr's default look in a team's colours (`{ league, team }`). Each theme takes its reactablefmtr arguments as options (`fontSize`, `fontColor`, `headerFontSize`, `headerFontColor`, `backgroundColor`, `cellPadding`) and reactable's `striped` and `highlight`; the highlight fills the hovered row, on by default in `fmtr-hoverdark` and `fmtr-hoverlight`. Text is gated at 4.5:1 (header labels, group headings, body type on every ground) and the row cues at 3:1; a failing reactablefmtr colour moves only as far as it must, keeping its hue (the table-themes guide lists each one). `FMTR_THEME_NAMES` lists the 27, and `GT_ALIASES` maps each reactablefmtr name to its theme. New decoration `legendIcon`, reactablefmtr's `add_icon_legend`: reactablefmtr's ski-rating, medal and battery icon sets, or your own shapes, drawn as inline SVG (`iconSet` or `icons`, not both; reactablefmtr's `centered` is not ported).
- ce0d7da: 122 more table themes, each named after the source it is styled on (`datagolf`, `basketball-reference`, `wikipedia`, `economist`, `nejm`, `espn-site`, ...), from a survey of newsroom, sports-stats, finance, journal, government and table-library tables. Use one by name like any other theme (`theme: { name: "datagolf", options: { mode: "dark" } }`); `mode: "dark"` works for the 98 themes with a dark version and raises a clear error naming dark alternatives for the rest. `listTableThemes()` lists them with their category and dark support. House themes and the `fmtr-*` reactablefmtr ports keep precedence over registry names. Faces load from Google Fonts with a serif, monospace or sans-serif fallback, and an unknown theme name now suggests close matches. The registry ships as `data/table_themes.json` and is shared byte-for-byte with sdvplot (Python) and sdvplotR.

### Patch Changes

- e2e1464: Data-driven colour columns (`colorRef` on `dataBar`, `colorRanks`, `colorPills` and `bubble`, and `iconSet`'s `iconColorRef`) accept the 148 CSS colour names (case-insensitive, trimmed: `"red"`, `" SteelBlue "`) as well as hex, as reactablefmtr does. A name resolves to its `#rrggbb` before rendering, so contrast ink is computed against the real colour and only hex reaches CSS. `transparent`, unknown names, `rgb()` / `hsl()`, `var()`, `url(...)` and blanks still render blank.

## 0.1.0

### Minor Changes

- 0b91a00: Static tables: serializable `TableSpec` with a `defineTable` builder, 21 column kinds, 25 decorations, 18 gtUtils themes plus `sdv` (light/dark) and `sdvTeam`, `renderHTML`/`toElement`/`themePreview`/`styleSheet` under `@sportsdataverse/sdvtables/html`, and the `GT_ALIASES` map from every sdvplotR `gt_*` name.
- fa3ce31: Interactive tables and PNG export:

  - `createTable(spec, rows, { pageSize, sort })`, a headless engine with no table-library dependency: sort (typed comparators, a column's own `compare`, missing values last both ways), per-column and global text filters, paging, `toggleColumn`, `setRows`, immutable snapshots and `subscribe`. Pure helpers `applyFilters`, `applySort`, `paginate`, `comparatorFor`, `withMissingLast`, `nextSortDir`, `findColumn`, `isMissing`, `NUMERIC_KINDS`. For linked figures: `rowKey` (spec and builder), `rowId`, `setExternalFilter` (takes sdvplot's `RowFilter`, so a selection store's brush applies as it is), `setSelection`/`getSelection`, `setHover`/`getHover`, and `select`/`hover` events.
  - `renderHTML(table)` in `@sportsdataverse/sdvtables/html`: sort buttons with `aria-sort`, a search box, per-column filter boxes and a pager. `hydrate(el, table)` progressively enhances server-rendered markup, re-rendering only the table block and batching changes into the next animation frame. A keyboard grid (`role="grid"` with one roving tab stop; `j`/`k`/`h`/`l`/`s` and `/` hotkeys, arrows, Enter/Space row selection; `interactive: { hotkeys: false }` keeps only the arrows, Enter and Space) through `handleKeydown`/`keyAction` and the engine's `TableCursor`. `handleClick`, `handleInput`, `handleHover`, `rowIdAt`, `renderInteractive`, `renderParts`, `assemble`, `tableHTML`, `attrsText`, `sortAria`, `tableRenderOptions`, `renderToolbar`, `renderPager` and `pagerLabel` serve custom renderers. Colour scales and legends span all rows, so a value keeps its colour while the user pages, filters or sorts; `selectRows` takes a `source` argument for index selectors.
  - Row hover: an interactive table underlines the row under the pointer, or the row a linked figure hovers (`sdvt-hover`, a text-coloured underline at 3:1 or better in every theme). Opt out with `tr.sdvt-hover>td.sdvt-cell{background-image:none}`.
  - `@sportsdataverse/sdvtables/react`: `useTable` and `<SdvTable/>`, whose server-rendered markup equals `renderHTML(table, { fonts: false })` and which is safe under React StrictMode; `fontsLinkFor(spec)` is the fonts `<link>` for the page head (`react` >= 18, an optional peer).
  - `@sportsdataverse/sdvtables/export` (Node): `tableToPNG`, `htmlToPNG`, `socialCrop`, `batchToPNG`, `gridTables`, `stackTables`, `composePage` and `slug` (options `PNGOptions`, `SocialCropOptions`, `BatchOptions`), ports of sdvplotR's `gt_save_crop`, `gt_social_crop`, `gt_save_batch`, `gt_grid` and `gt_stack_tables` with the Python defaults (`playwright`, an optional peer).

### Patch Changes

- 4049e84: A host page's global table CSS no longer restyles an sdvtables table. Observable Framework's `td { color }` and `table { font }` rules beat the ink and type a cell only inherited from the table root, and Docusaurus (Infima) painted its stripe on every second row: in dark mode a dark theme on a light page, or a light theme on a dark page, fell to about 1.0–1.6:1 contrast. Cells now take their row's ink explicitly (`color: inherit`, at specificity (0,1,0), so an element-only host rule loses and an author's class-qualified rule such as `.page td { color }` still wins), the table inherits the root's font, rows drop a host's background and rules, and cells drop its borders (Infima borders every cell). sdvtables itself never styles a `<tr>`, and the theme renders on a bare page are unchanged.
