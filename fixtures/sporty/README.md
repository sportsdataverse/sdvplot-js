# sporty oracle fixtures

R truth captured from sportyR's built ggplot layers (every `GeomPolygon` layer in draw order as `layer_NNN.csv`, every `ggfittext` `GeomFitText` layer as `text_NNN.csv` — box centre `x, y`, `label`, `angle`, on its own counter — plus `coord_fixed` limits per display range).

- sportyR: 2.3.0 (git 811c483, branch `fix/geometry-quirks` = sportyR PR #68, not yet merged)
- R: 4.6.1 (2026-06-24)
- Generated: 2026-10-18, every sport
- Command: `pnpm oracle:sporty basketball hockey football soccer baseball tennis volleyball curling lacrosse softball` (repo root), with `R_LIBS` pointing at a private library holding that sportyR (`R CMD INSTALL --library=<lib> <sportyR checkout>`) and `SPORTYR_REPO` at the checkout

The fixtures were generated by that locally installed sportyR 2.3.0 build, whose `surface_dimensions` was verified `all.equal` to the vendored `packages/sporty/data/surface-dimensions.json` at sha256 `544e29f1b7a65581ddc6b7f798a38367eb49e494734e6a224df2c374d7ed4fe1` (vendored from sportyR git 811c483, DESCRIPTION 2.3.0). Against the 2.2.3 fixtures, soccer, tennis, baseball, curling and volleyball are byte-identical; basketball and hockey differ only in the last digits of some values (|Δ| ≤ 1.1e-13, far inside the 5e-10 parity tolerance: the local build versus the CRAN binary); lacrosse and football carry the sportyR #60-#67 fixes (`field_bordered` outlines on NCAA, NFHS and NFL; the NCAA coaching line). The oracle stops before writing anything if that check fails, and records the sha in `VERSION`; `packages/sporty/test/fixtures-version.test.ts` fails CI when the vendored JSON, its sportyR version or its checkout no longer match `VERSION`.

Never hand-edit; a mismatch is a TS bug. Consumed by `packages/sporty/test/parity.test.ts`.
